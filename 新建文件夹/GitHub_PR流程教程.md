# GitHub Pull Request（PR）完整流程教程

## 前言

Pull Request（简称 PR）是 GitHub 上最常用的代码协作方式。简单来说，PR 就是你在自己的分支上完成代码修改后，向项目维护者发出的一个"合并请求"——请对方审查你的改动，并在确认无误后合并到主分支中。

本文将通过一次实际操作，带你完整走一遍 PR 的全流程。

## 前置准备

在开始之前，请确保你已经完成以下准备：

- 注册一个 GitHub 账号
- 本地已安装 Git
- 已将远程仓库克隆到本地（`git clone`）
- 已配置好 Git 用户名和邮箱

## 第一步：创建自己的分支

在修改代码之前，先从主分支（通常是 `main` 或 `master`）创建一个新的分支，避免直接修改主分支：

```bash
git checkout -b 你的分支名
```

> 💡 分支名建议有辨识度，比如 `feature/homework-01` 或 `fix/typo-in-readme`，方便后续识别。

## 第二步：修改代码并提交

在分支上完成你的代码修改后，使用以下命令将改动暂存并提交：

```bash
git add .
git commit -m "简要描述你做了什么修改"
```

> 💡 提交信息（commit message）建议写清楚本次修改的内容，比如"修复了 README 中的拼写错误"，而不是笼统地写"update"。

## 第三步：推送分支到 GitHub

将本地的分支推送到远程仓库：

```bash
git push origin 你的分支名
```

推送成功后，你的分支就会出现在 GitHub 的远程仓库中。

## 第四步：在 GitHub 网页上发起 Pull Request

1. 打开 GitHub 上对应的仓库页面
2. 页面顶部通常会出现一个黄色提示条，显示 **"Compare & pull request"**，点击它
3. 如果没有看到提示条，可以点击顶部的 **"Pull requests"** 标签，再点击 **"New pull request"** 按钮
4. 确认 **base**（目标分支，即你要合并到的分支，通常是 `main`）和 **compare**（你的分支）选择正确
5. 填写 PR 的标题和描述：
   - **标题**：简要概括本次修改，例如"完成第一次作业"
   - **描述**：详细说明你修改了哪些内容、修改的原因等
6. 确认无误后，点击 **"Create pull request"** 按钮

> 💡 一个好的 PR 描述可以帮助审查者快速理解你的改动意图，建议多写几句说明。

## 第五步：等待审查与反馈

PR 创建成功后，项目维护者（maintainer）会收到通知并进行代码审查。

- 如果维护者提出了修改意见，你需要根据反馈在本地继续修改代码，然后再次 `git add`、`git commit`、`git push`，PR 页面会自动更新你的最新改动
- 如果维护者没有回复，说明本次练习的目的已经达到，你已经成功走通了整个 PR 流程

## 常见问题

**Q：PR 和直接 push 到 main 分支有什么区别？**

A：直接 push 到 main 分支会立即修改主分支的代码，容易造成冲突和混乱。而 PR 提供了一个审查和讨论的环节，确保代码质量。

**Q：PR 被拒绝（close）了怎么办？**

A：不用紧张，PR 被拒绝是很正常的。仔细阅读维护者的反馈意见，修改后重新提交即可。

**Q：一个 PR 可以包含多次 commit 吗？**

A：可以。你在分支上的所有 commit 都会包含在同一个 PR 中，直到 PR 被合并或关闭。

## 总结

整个 PR 流程可以概括为以下几步：

1. 创建分支（`git checkout -b`）
2. 修改代码并提交（`git add` + `git commit`）
3. 推送到远程（`git push`）
4. 在 GitHub 网页上创建 PR，填写标题和描述
5. 等待审查反馈，根据意见修改

掌握 PR 流程是参与开源项目和团队协作的基础，建议多加练习，熟悉每一步操作。
